# 实施计划

依据 `doc/需求.md`（v 定稿）编写。共分 7 个阶段（阶段0~6），每阶段有明确验收标准，完成一个阶段即得到一个可运行的中间版本。

## 总体架构约定

- 依赖方向单向：**渲染层 → 业务层 → 数据层**；反向通知一律用 Qt 信号/槽（如数据变更 → 刷新视图）
- **所有修改操作从第一天起就走业务层的命令类（Command 模式）**，阶段4 只需补撤销栈管理，避免返工
- 坐标存储统一用 cm（浮点）；QGraphicsScene 中约定 **1 场景单位 = 1cm**，缩放交给 QGraphicsView 的 transform
- 朝向角度：需求规定 0°=y 轴正方向、逆时针增大；Qt 的 `rotate()` 在 y 向下坐标系中为顺时针正值。**封装统一转换函数，业务/数据层只使用需求角度，仅渲染入口换算**
- 数据模型：对象 = 静态变换（位置+朝向）+ 关键帧列表；游标在时刻 T 的取值 = 关键帧插值结果，无关键帧时用静态值

## 存档 Schema 草稿（数据层阶段定稿）

```json
{
  "version": 1,
  "stage": { "width": 1200, "depth": 800, "centerOffset": 0 },
  "objects": [
    {
      "id": "actor-001", "type": "actor", "name": "张三", "color": "#e74c3c", "parent": "",
      "transform": { "x": 300, "y": 200, "rotation": 0 },
      "keyframes": [ { "t": 2.0, "x": 300, "y": 200, "rotation": 0 } ]
    },
    {
      "id": "screen-001", "type": "screen", "name": "屏风1", "color": "#888888", "parent": "group-001",
      "size": { "w": 100, "h": 10 },
      "transform": { "x": -150, "y": 100, "rotation": 90 },
      "keyframes": []
    },
    {
      "id": "group-001", "type": "group", "name": "空对象1", "parent": "",
      "transform": { "x": 0, "y": 0, "rotation": 0 },
      "keyframes": []
    }
  ],
  "timeline": { "duration": 60.0, "labels": [ { "t": 0.0, "name": "第一幕" } ] }
}
```

- 单位：长度 cm、时间秒、角度度（需求角度制）
- `version` 字段用于将来格式迁移（已确认，需求第 19 条已同步）
- 舞台矩形范围：x ∈ [centerOffset − width/2, centerOffset + width/2]，y ∈ [0, depth]，原点为最里边中点
- `type` 预留 `"prop"`（道具占位）
- `parent` 字段（Hierarchy 树形整理）：父对象 id，空串 = 顶层对象；**读取缺省视为顶层（旧存档可直接加载），写出始终包含**。列表顺序 = Hierarchy 深度优先显示顺序（子对象紧跟其父的子树区间）
- `type` 另有 `"group"`（空对象/分组）：纯组织节点——不渲染、不可视口选中、无颜色/大小属性（transform/keyframes 保留默认值）、不影响子对象坐标（无变换继承）；删除分组级联删除整棵子树

## 目录结构

```
CMakeLists.txt
src/
  main.cpp
  data/        # 数据层：DataTypes / JsonStore / AppSettings(QSettings) / RuntimeData
  business/    # 业务层：EditorCore / Commands(撤销) / SelectionModel / TimelinePlayer(插值与播放)
  render/      # 渲染层：MainWindow / StageView / StageScene / *Item / HierarchyPanel / InspectorPanel / TimelineWidget / dialogs/
```

## 阶段0：项目骨架（约 0.5 天）

任务：
1. CMakeLists.txt：Qt6 Widgets、C++17、WIN32 可执行、MSVC 2022 工具链
2. 按上面目录结构建空模块
3. MainWindow：QDockWidget 布局——左侧 Hierarchy、右侧 Inspector、中央主视口、底部时间轴（后三者先放占位 widget）
4. 菜单栏：文件（新建/打开/保存/另存为/退出）、编辑（撤销/重做/复制/粘贴/删除）、舞台、设置（菜单项先占位禁用）

验收：编译通过，空壳窗口运行，三栏 Dock 可拖拽调整，菜单可见。

## 阶段1：数据层（约 2~3 天）

任务：
1. DataTypes：StageData、ObjectData（含 Keyframe）、TimelineData、FileData（对应 Schema 草稿）
2. AppSettings：常量（演员半径30、屏风默认100×10、网格100、吸附范围20、方向键步长10、默认调色板）+ QSettings 持久化用户设置（吸附开关、"不再提示"开关、窗口布局）
3. JsonStore：`load(path) → Result<FileData, 错误枚举>` / `save(path, FileData)`；损坏文件返回专门错误；version 检查
4. RuntimeData：软件数据 + 文件数据组合，提供只读访问接口；保存由业务层显式调用

验收：临时测试代码构造数据 → 保存 → 读回 → 字段逐一比对一致；损坏 JSON 返回错误而非崩溃。

## 阶段2：主视口渲染（只读）（约 2~3 天）

任务：
1. StageScene/StageView：`drawBackground` 画 100cm 网格与原点标记；舞台矩形（按 centerOffset）
2. ActorItem（圆+白三角）、ScreenItem（矩形），由 RuntimeData 生成；数据变更信号 → 重建/更新
3. 视口交互：滚轮缩放（`anchorUnderMouse` 以鼠标为中心）、右键拖动平移（拖动后松开不弹右键菜单）；不做相机旋转
4. 默认视图比例 1:50

验收：加载手工编写的示例 JSON，舞台/演员/屏风位置朝向显示正确；缩放平移顺滑；角度换算经用例验证（0° 朝下、90° 朝左）。

## 阶段3：编辑交互 + Hierarchy + Inspector（约 4~5 天）

前置：业务层先定义 Command 基类（`apply()/revert()`），本阶段所有修改都实现为命令。

任务：
1. SelectionModel（业务层）：单选 / Ctrl 多选 / 框选（中心点判定）/ 点空白取消；多选状态广播
2. 移动：拖拽（多选整体移动）、方向键 10cm、网格吸附（20cm 范围，读设置开关）
3. 旋转：拖拽演员白三角改变朝向（屏风同理用朝向手柄）
4. 创建：视口/Hierarchy 空白右键 → Create → 类型选择对话框（道具禁用）→ 视口按右键位置 / Hierarchy 按 (0,0)
5. 删除 / 复制 / 粘贴（默认偏移 x+20,y+20；右键菜单粘贴落在鼠标位置）
6. HierarchyPanel：QTreeWidget 列表，与视口选中双向同步，名字与 Inspector 一致
7. InspectorPanel：单选显示表单（演员：角色名/位置/朝向/颜色；屏风：+大小），修改即时生效；多选时清空
8. 名称唯一性校验（重名拒绝并提示）

验收：对照需求第 11~14 条逐项手测通过；所有操作均经过命令类。

## 阶段4：撤销/重做（约 2 天）

任务：
1. UndoStack（业务层）：命令入栈、撤销、重做、栈清空时机（新建/打开文件）
2. 编辑菜单 + 快捷键（Ctrl+Z / Ctrl+Y）接入
3. 覆盖范围：主视口、Hierarchy、Inspector 中的一切修改（移动、旋转、创建、删除、粘贴、改名、改属性）；时间轴操作在阶段5 接入同一撤销栈

验收：随机操作序列 20 步后逐级撤销回初始状态，再逐级重做一致。

## 阶段5：时间轴（约 6~8 天，核心阶段）

任务：
1. TimelineWidget（底部 Dock）：秒标尺、轨道区（每对象一行、同类可折叠）、关键帧点、可拖动游标、场次标签行
2. TimelinePlayer（业务层）：游标定位 → 逐对象插值（位置直线匀速、朝向最短弧匀速、首前/末后保持）→ 发信号驱动视口与 Inspector 显示当前时刻值
3. 打帧按钮 + 需求第 20 条流程：游标处已有该对象关键帧 → 直接更新；否则按设置弹窗询问（可"不再提示"）；Inspector 修改走同一流程
4. 关键帧编辑：单击选中、长按左键拖动改时刻、Delete 删除；与场次标签编辑一起全部实现为命令并进撤销栈（已确认，见需求第 14 条）
5. 播放 / 暂停 / 倍速：QTimer 驱动游标，视口联动
6. 场次标签：添加、改名、显示（纯视觉标记）
7. 时长延长：关键帧或标签超出当前时长时自动延长

验收：创建 2 个演员各打 3 个关键帧，播放时走位动画正确；游标拖动实时联动；场次标签显示正常；时间轴上的关键帧移动/删除可撤销、重做且游标处显示立即刷新。

## 阶段6：舞台设置与文件流程收尾（约 2~3 天）

任务：
1. 舞台设置对话框（顶部菜单<舞台>打开）：宽/深/中心点偏移，应用后视口与网格刷新
2. 文件流程：新建 / 打开 / 保存（Ctrl+S）/ 另存为；损坏文件提示；另存为重名覆盖确认
3. 未保存 `*` 标记（标题栏文件名后）；退出、新建、打开文件时若未保存均提示（已确认，见需求第 16 条）
4. 设置对话框：吸附开关、"不再提示"开关
5. 整体联调 + Windows 打包试运行

验收：从新建到编排、打帧、保存、关闭重开的完整流程走通，无数据丢失。

## 已确认决策

1. **时间轴操作进撤销栈**：关键帧的移动/删除、场次标签的编辑与主视口/Hierarchy/Inspector 操作同等对待，全部走命令类（需求第 14 条已同步）
2. **version 字段**：schema 保留 `version: 1`（需求第 19 条已同步）
3. **未保存提示三入口一致**：退出 / 新建 / 打开均提示（需求第 16 条已同步）
4. **道具对象**：仅预留 `type` 枚举与禁用菜单项，不产生其他工作量

## 风险

1. 角度换算是最容易出隐蔽 bug 的地方，阶段2 验收时重点验证
2. 撤销与时间轴耦合：撤销/重做关键帧命令后，游标处的插值结果要立即刷新，阶段5 验收已覆盖此场景
